# PokeMog Data

Validated, standalone public Pokemon GO data derived from [PvPoke](https://github.com/pvpoke/pvpoke).
No Android, web application, APK, secrets, or user data is hosted here.

## Client Contract

Latest release: https://api.github.com/repos/TicTacTris/pokemog-data/releases/latest

GitHub immutable releases are enabled. Each release uses a unique,
never-overwritten `data-<datasetVersion>` tag. Download
`manifest.json` and the four assets individually; there is no ZIP data pack:

- `pokemon.json`: id, name, attack, defense, stamina, evolutions, optional normalId/shadowId.
- `cp-multipliers.json`: exactly 101 finite, strictly increasing values between 0 and 1, indexed by `(level - 1) * 2`, levels 1 through 51.
- `evolution-metadata.json`: provenance commit and graph warnings/corrections.
- `PVPoke-LICENSE.txt`: unmodified upstream MIT license.

Manifest shape (placeholders below are descriptive, not JSON literals):

```text
{schemaVersion:1, calculationContract:1,
 datasetVersion:<positive safe integer timestamp>, sourceCommit:<40 lowercase hex>,
 publishedAt:<ISO timestamp>, files:{
  "pokemon.json":{size:<byte count>,sha256:<64 lowercase hex>},
  "cp-multipliers.json":{size:<byte count>,sha256:<64 lowercase hex>},
  "evolution-metadata.json":{size:<byte count>,sha256:<64 lowercase hex>},
  "PVPoke-LICENSE.txt":{size:<byte count>,sha256:<64 lowercase hex>}}}
```

`sourceCommit` always equals the metadata report's `commit`. Clients must verify
schema, calculation contract, all sizes and hashes before atomically installing
the whole pack. GitHub's automatic source archives are not dataset assets.

## Validation and Publishing

Requires Node 22; no npm dependencies. Run `npm test`.
`node tools/update.mjs` generates and validates a candidate without publishing.
`node tools/update.mjs --publish` publishes only relevant output changes.
GitHub CLI authorization or GH_TOKEN is needed for API access.

The workflow runs every six hours and via manual dispatch. Pushes and pull
requests test only. It resolves the upstream default branch and fetches both
gamemaster.json and Pokemon.js plus LICENSE at the same exact commit. Comparison
includes all generated bytes except the report's provenance-only commit field,
so unrelated upstream commits do not cause releases. License changes do count.

Validation rejects malformed numeric data, duplicate IDs, broken graph links,
cycles, nonreciprocal shadow pairs, and counts below 98% of either the initial
baseline or latest verified pack (minimum 1,000). Larger intentional removals
require a reviewed code change. CPM values may change while retaining the 101-value
shape; changes in formula, level mapping, or semantics require a manually reviewed
calculationContract change coordinated with clients, never automatic inference.

Publication creates a draft, uploads exactly five assets, downloads and verifies
every asset, then marks the release published/latest. No overwrite/clobber path
exists. Failed drafts remain unpublished for diagnosis; never manually publish
an unverified draft. Serialized workflow runs use only GITHUB_TOKEN with
contents:write in the publishing job. No PAT is stored.

The first manual run with `initial=true` regenerates the pin, asserts byte parity
against baseline, and publishes that exact baseline; later initial runs fail.
See [SOURCE.md](SOURCE.md) for corrections, fixture scope and licensing.

See [SECURITY.md](SECURITY.md) for limits, workflow controls and the trust model.
Hashes verify manifest consistency, not independent publisher authenticity.
Synthetic accepted/rejected contract cases are in
`test/fixtures/contract-fixtures.json`; graph depth counts the root as 1 and
reachability includes the root. The frozen 147-row mathematical contract remains
independent of current upstream stats. No application repository is modified by
the publisher.
